## Routing

| Need | Route |
| --- | --- |
| Repository, team, ruleset, environment, or application defect | Open a sanitized issue in this repository |
| Governance change | Open a pull request with the evidence required by [CONTRIBUTING.md](CONTRIBUTING.md) |
| Access request | Use the approved identity and access workflow; do not request access in an issue |
| Enterprise manual control | Follow [docs/enterprise-manual-controls.md](docs/enterprise-manual-controls.md) |
| Security vulnerability or weakened control | Follow [SECURITY.md](SECURITY.md); never open an issue |
| Cloud-resource problem | Route to `mindclade/infrastructure-live` or `mindclade/bootstrap` |
| Contractual customer support | Use the channel and service terms in the applicable agreement |

GitHub issues do not carry an SLA. Do not include credentials, access tokens,
private keys, exports of repository membership, customer data, saved plans, or
incident-sensitive evidence. Use sanitized object identifiers and audit-event
references.

The applicable customer agreement or incident-response process controls if it
conflicts with this routing guide.
